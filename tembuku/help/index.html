Quick start (about two minutes)

  1. Open Tembuku. Click the Tembuku icon on the toolbar, or use Vector > Tembuku > Design Feeders...
  2. Choose your data folder. Put all KMZ files for the job in one folder and choose it. Tembuku reads every file and works out what each one is. If it guesses wrong, change the Read as column.
  3. Read the input check. Green lines were corrected automatically, amber lines need a look, red lines must be fixed before Tembuku can run. Each line ends with an arrow telling you what to do.
  4. Press Run all FDTs. Tembuku works in the background; QGIS stays usable. When it finishes, the report opens in your browser and the results appear on the map and in the panel on the right.
  5. Review and decide. Tembuku proposes; you decide. Open each FDT, read the reason, check the route on the map and adjust it if needed. The KMZ files are ready to copy into the feeder design compilation.
Tip: nothing to process yet? Press Prepare for map clicks and click anywhere on the map to get an instant recommendation for an FDT at that spot.

File names and formats do not matter. Tembuku looks inside every file and recognises what it is from the content: lines with fibre counts and spare-fibre data are a cable inventory; folders that hold both FDT points and cables (with F1_T1 names or any other names) are a design compilation; a list of FDT/ODC points is what you want designed; POP/OLT/STO points are POP locations. The Why column in the window and the section "Berkas yang dibaca dan alasannya" in the report say what was found in each file. If a file was recognised wrongly, change it in the Read as column.

The FDT is never moved. Tembuku uses the FDT point exactly as it is in your file. A point whose name is an FDT code followed by more text (for example GSK1-CUL01-H03-D01-01) belongs to distribution and is never used as the FDT. If the LAT/LONG fields, or the same FDT in the compilation, point somewhere else, Tembuku tells you in the input check and still keeps your point. Every result KMZ is opened again to confirm this.

Feeder tube record (optional). An Excel or CSV table with the columns Feeder and Tube Terpakai (and optionally POP) in the same folder is read together with the compilation, so the next T number takes the recorded tubes into account. T numbers never go past 12; when an unrecorded number is proposed, or all 12 are recorded, the result says so and asks you to verify.

Template and icons. Each result KMZ holds the complete Feeder folder set of the APD Feeder template, in the template order, with the template cable colours and line width; this is checked after writing. To use your own icons, put PNG files whose names start with what they show (FDT, Closure 48, Closure 96, Closure 288, OTB, OLT, Spare or Slack) in the folder ikon next to istilah.json (QGIS profile folder > tembuku) or in Documents/Tembuku/ikon. They stay on your computer and are stored in the KMZ under neutral names. Lines in the Colo Pole folders take the colour of their cable size, as in the template.

File names. The design KMZ is named like the feeder design files used in the compilation: <cluster ID>_APD Feeder KMZ_<area>_<date>.kmz. When the cluster ID or area is not in your data, the FDT code is used instead (TEMBUKU_<FDT>_<decision>.kmz). The summary CSV lists which file belongs to which FDT.

Two KMZ files per FDT. The design KMZ holds only the template folders, so a bill-of-materials tool reads nothing extra. The file ending in _ANALISIS holds the review material: the candidates compared, their tap points, helper lines to redraw, and stretches that need new poles or a new route.

Formats read: KMZ and KML (also when the extension is wrong), ZIP files holding several of these, GeoJSON, CSV or TXT with coordinate columns (lat/lon in any common spelling, one "lat, lon" column, or WKT; decimal comma is fine), Excel (.xlsx), and through QGIS also Shapefile, GeoPackage, GML, MapInfo TAB, FlatGeobuf and GPX. Column names in Indonesian or English are understood (e.g. kode ODC, core cadangan, spare), and attributes kept only in the description table of a KMZ are read too. Presentations, documents and pictures in the folder are skipped. Very large inventory files are fine; the first run builds a small index of your work area (a few seconds), later runs reuse it.

New in 1.4.0. Free tubes are read from the folders of the feeder design compilation only: one feeder is one 144-fibre trunk of 12 tubes, and the T number of a folder (F2_T9) is the tube it uses. T1-T8 go through the 96-fibre cable, T9-T12 through 48-fibre branches from the closure 144 at the POP. Tembuku proposes the lowest free tube of the group that fits the 6 km rule, prefers a tap at an existing slack or closure, and can propose a new 48-fibre branch from the closure 144 of an existing feeder. The cable inventory is used as existing pole routes only. When two feeders are equally good, the lowest feeder number is used and the other is listed for you to choose.
New in 1.4.4. The engineering rules were checked against technical sources and 213 approved designs. Two rules can be switched on under Advanced but are off or limited by default because they cost cable without a better design: the tube group by 6 km distance, and reaching an existing slack at any cost (now: at most 600 m or 15 % more cable). Mid-span taps stay marked please check.
New in 1.4.3. Every result starts with one plain sentence: what to build, which F/T folder, how much new cable, and what a new feeder would need instead. Tembuku takes the lowest free tube of the feeder, as the designers do, prefers a tap at an existing slack, closure or cable end, and marks with please check every tap that is mid-cable and every tube number that the compilation does not record yet.

Marks you may see

  • Please review (perlu ditinjau): using an existing feeder and building a new one are almost equally good. Look at both before deciding.
  • Straight helper line (garis bantu, red dashes): there was no road or cable data on that stretch. Redraw it along the poles or the road before construction.
  • Accuracy test: when you run Accuracy test, each FDT already designed in the compilation is hidden and designed again, and the report compares Tembuku with the designer (same decision, same folder, tap point distance, route match).

The candidate table

For every FDT, Tembuku lists the existing feeders nearby and what it found for each one:

  • Free tubes: whether the feeder still has a whole tube (12 fibres) free for this FDT.
  • New cable to FDT: the new cable from the tap point on that feeder to the FDT, and how much longer it is than a straight line.
  • Direction: the angle between the feeder and the way to the FDT, seen from the POP. 0° points straight at the FDT; more than 60° (the default limit) means the feeder runs away from it.
  • Route vs new feeder: the route through this feeder (POP to tap point plus the new cable) compared with a new feeder straight from the POP. 1.00× is the same length; above 1.24× (the default limit) the route is a long way round.
  • Signal loss: the total loss of light from the POP to the customer and how much is left before the GPON class B+ limit of 28 dB.
  • Result: Meets every condition, Usable, but ... (something to check on site), or Rejected: ... with the reason in plain words.

On the map

Tembuku adds a group of layers: Proposed cable route (coloured by type: existing poles, new poles, helper line), Existing feeder used (POP to tap point), Candidate feeders, FDT, POP and tap points, and, in the accuracy test, Designer's own design. In the panel, double-click another candidate to use it instead.

Click on the map

Press Prepare for map clicks once, then switch on Click an FDT on the Map and click. Each click is designed in about a second. Clicking outside the prepared area simply adds that area first.

The input check

Real files contain small mistakes. Tembuku follows the data-quality terms of ISO 19157-1 and the robustness principle as re-examined in RFC 9413: it corrects only what has one clear answer, always tells you what it corrected, and stops when it cannot be sure.

  • Corrected automatically: e.g. FDT folder spelt FTD, extra spaces, a comma used as decimal point.
  • Please check: e.g. a cable size like 441C that is probably 144C, or two FDT codes that disagree.
  • Cannot run: a file that does not exist, is damaged or unsafe, or a required source is missing. Tembuku suggests files with similar names if you mistyped a path.

How decisions are made

  1. Find the POP serving the FDT (nearest, within 20 km: the GPON physical reach of ITU-T G.984.1).
  2. List candidate feeders within 3 km. Only fibre-to-the-home feeders of at least 48 fibres may give fibres; other cables are used only as existing pole routes.
  3. Free tubes: from the spare-fibre count (spare ÷ 12 per tube) or, for on-going feeders, tubes minus the FDTs they already serve. One FDT uses one tube.
  4. Direction: the feeder must run toward the FDT as seen from the POP (at most 60° off), and the route through the tap point must not be more than 1.24 times a new feeder from the POP. This limit was calibrated on 17 approved real designs.
  5. Route: the cheapest path from the tap to the FDT along existing poles, roads and short access links (a shortest-path search, the standard engineering rule in FTTH planning research). Existing poles are preferred.
  6. Optical budget: fibre loss, splitters, connectors, splices and a 3 dB margin must stay within GPON class B+ (28 dB). Tembuku uses the standards' maximum values, so the check is on the safe side.

All settings can be changed under Advanced in the Tembuku window. Changed values are highlighted, and Restore default values brings back the calibrated defaults.

Glossary

FeederThe main cable from the POP toward the customers' area.
FDTFibre distribution terminal: the cabinet near customers where a feeder tube is split.
FATFibre access terminal: the small box on a pole that serves a few houses.

New infraStretches that need new poles or a new path.

Company labels (optional)

Tembuku ships with neutral labels and contains no company or brand names. To make the KMZ match your company's template exactly, place a file istilah.json in Documents/Tembuku/ (or in the QGIS profile folder tembuku/). It stays on your computer and is never part of the plugin. Each rule in aturan_label_colo is [column, text, label]: the label is used when the column contains the text, or starts with it when the text begins with ^. Rules are checked in order. Example:

{
  "label_tiang_nasional": "Colo Pole (your company)",
  "label_colo_compile": "Colo FTTH (on going)",
  "aturan_label_colo": [["Owner", "PARTNER", "Colo Partner"], ["Owner", "^ABC", "Colo ABC"]],
  "petunjuk_berkas_nasional": ["CABLE INVENTORY"],
  "atribut_pop": ["Site_ID"]
}

Background maps: OpenStreetMap and current satellite imagery

Choose Vector > Tembuku > Basemaps (or the Basemap button in the results panel). Tembuku offers only maps that are current and whose date you can see: a design made in 2026 must not be checked against a picture from years ago, when houses and roads that exist today were not there yet. Layers are added under the Tembuku results and are streamed live, never stored for offline use, as the providers require.

Is the picture old? Basemaps > When was the detailed satellite image here taken? reads the date at the map centre at any time. If it is older than 12 months, Tembuku shows a warning: anything built after that date is not in the picture, so compare with OpenStreetMap, the Copernicus mosaic or a field survey. The HTML report does the same: switch to the detailed layer and the date of the place in the middle of the map appears at the bottom left, with the same warning.

Anywhere in Indonesia: all three maps cover the whole country. When your data moves to another area, just pan there: the Copernicus layer always shows the newest quarter and the Esri date is read again for the new place. When QGIS starts or a project opens, Tembuku moves the Copernicus layer to the newest quarter and re-reads the Esri date by itself.

One-time setup for the cloud-free Copernicus mosaic (free, about 5 minutes)

  1. Create a free account at dataspace.copernicus.eu (Copernicus data are free for any use, including commercial).
  2. Open the Sentinel Hub dashboard of the Copernicus Data Space Ecosystem and choose Configuration utility > New configuration.
  3. Add a layer: data source Bring your own COG, collection byoc-5460de54-082e-473a-b6ea-d5cbe3c17cca (Sentinel-2 L2A quarterly cloudless mosaics), with the true-colour script offered for that collection. Give the layer a short name, e.g. TRUE-COLOR.
  4. In QGIS choose Basemaps > Satellite - newest cloud-free, change check and paste the configuration's instance ID and the layer name, separated by a space. Tembuku remembers them; Forget my saved keys removes them.

The free account allows about 10,000 tiles per month, enough for one engineer. A whole team should each use their own account, or the company can buy a larger plan.

Honest limits. No source is at the same time cloud-free, new every day, sharp enough to see a house and free. Near the equator clouds cover a place on most days, so a cloud-free picture is always a mosaic of several weeks or months: the Copernicus mosaic is the newest such picture (at most about 4 months old, older only where clouds never cleared) but is 10 m per pixel. Sharp imagery (Esri) shows houses but its date differs from place to place, which is why Tembuku always shows it. Always confirm poles and new buildings in the field.

Why only these sources: OpenStreetMap tiles may be used interactively with attribution, but not stored for offline use (OSMF Tile Usage Policy); for that reason the offline report carries road lines (data) instead of map pictures. Copernicus Sentinel data are free for any use, including commercial. Esri imagery may be used in other software only with an ArcGIS key; its capture dates come from Esri's official World Imagery metadata service. Not offered: the 2016 Sentinel-2 cloudless mosaic (too old), NASA daily/HLS imagery (375 m and 30 m, often cloudy), later EOX mosaics and Planet NICFI (non-commercial licences; NICFI ended in January 2025), Google and Bing (their terms do not allow direct tile access). Your Esri key or Copernicus instance is put in the HTML report only if you allow it under Advanced, because anyone who receives the report could then use it.

Privacy and internet

  • Your files never leave your computer. Tembuku reads KMZ files without unpacking them to disk and rejects unsafe content. ZIP bundles are unpacked only into Tembuku's own cache folder, with limits on size and number of files.
  • Internet is used only for road lines from OpenStreetMap around your FDTs (once per area, kept for 90 days) and for the basemaps you choose to show. Nothing about your data is uploaded. You can switch this off, or use your own road layer under Advanced.
  • The public road server is free and shared. Its operators ask heavy, regular users (such as companies) to use their own or a paid server: enter its address under Advanced > Road data server.
  • The cable index keeps only the geometry and attributes needed for the decision (data minimisation, Law 27/2022).

Problems?

The Run button is greyThere is a red item in the input check, or no target FDTs. Fix the red item and press Check again, or use map clicks.
Many red dashed linesRoad data was not available (offline or server busy). Run again later, or choose your own road layer under Advanced.
"OpenStreetMap server busy"The public server is overloaded. Tembuku waits 30 to 60 seconds and retries, as the server's rules ask. Areas that fail are tried again on the next run.
A file was read as the wrong typeChange it in the Read as column.
Something elseOpen View > Panels > Log Messages > Tembuku and send the text to the author.
