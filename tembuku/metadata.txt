about=Tembuku turns the first stage of FTTH/GPON feeder design into a one-folder task in QGIS. Point it at a folder of map data (cable inventory, feeder design compilation, the FDT points to design, POP list) as KMZ/KML, ZIP, GeoJSON, CSV/Excel or Shapefile/GeoPackage: Tembuku recognises each file from what is inside it, not from its name, says why, lists and corrects small typing mistakes in folder names, FDT codes and coordinates, and stops with a clear message when a required file is missing or unsafe. For every FDT it (1) checks the free tubes of nearby feeders and whether each feeder really runs toward the FDT, (2) picks the tap point and draws the new cable along existing poles and roads (OpenStreetMap, cached), (3) checks the GPON optical budget with the maximum values of current ITU-T standards and (4) decides between reusing a feeder and building a new one from the POP, with the reason written out. Results: KMZ files in the compilation folder layout with automatic F/T numbering, styled QGIS layers, an interactive offline HTML report, a CSV summary and an accuracy test against designs already approved (17 of 17 decisions matched on the Bitung and Tomohon designs used to calibrate the rules). Click an FDT on the map for an answer in about a second, or choose another candidate in the results panel. Basemaps show only current imagery with a known date: OpenStreetMap, detailed satellite imagery with the capture date at the map centre and an age warning, and the newest cloud-free Copernicus Sentinel-2 mosaic for the whole of Indonesia. Every value can be changed and names its source; no company names are built in (optional company labels stay in a local file). Large KMZ files are indexed once per work area and read safely (no extraction, size limits, no DTD). No extra Python packages. Interface in English; reports in Indonesian. changelog=1.2.1 Progress you can see: while Tembuku works in the background, the Tembuku panel now shows a progress bar with the percentage and the current step (for example 'Designing feeders: 40% - Designing FDT FDT-12 (4/10)'), the percentage in the panel title, and a Cancel button; previously the progress was only in the small QGIS task bar at the bottom right. Applies to designing feeders, preparing data for map clicks, the accuracy test and clicked FDTs. No change in design results. 1.2.0 Plain language everywhere, so that people new to feeder design can follow every result: decisions and reasons are written as short sentences that start with the verdict; candidate feeders show "meets every condition", "usable, but ..." or "rejected: ..." with the reason in words (direction in degrees instead of a cosine, "route vs new feeder" instead of a ratio code, signal loss and what is left before the limit); input-check messages, the results panel, layer names and attribute fields in QGIS are fully in English, while the report, KMZ and CSV stay in Indonesian with readable column names and decision names instead of internal codes. Neutral vocabulary that fits any operator (cable inventory, feeder design compilation, KMZ with FDT points). Safety: an FDT that cannot be analysed is never dropped - it stays in every output as "Needs manual design" with the reason; text from KMZ files is fully encoded in the HTML report. Seventeen damaged or unusual input cases (empty, damaged or unsafe files, no POP, swapped coordinates, FDT outside Indonesia or 40 km from the POP, duplicate FDTs, odd cable sizes, two versions of a compilation) are tested and handled with a clear message. Smarter file recognition: every file is recognised from what is inside it, not from its name or extension - cable lines with fibre and spare-fibre data, folders holding both FDT points and cables (with or without F1_T1 names), lists of FDT/ODC points, POP/OLT/STO points - and the window and report say why. New formats: ZIP bundles, GeoJSON, CSV/TXT/Excel with coordinates (any common lat/lon spelling, WKT, decimal comma), and through QGIS Shapefile, GeoPackage, GML, TAB, FlatGeobuf and GPX; Indonesian and English column names and attributes kept in KMZ description tables are understood; damaged files are named clearly. Calculations and decisions are unchanged: the 17 test FDTs give exactly the same results as 1.1.1, and the same targets given as KMZ, CSV, GeoJSON or Excel give identical decisions. 1.1.1 Clearer plugin description and changelog; code-quality fix reported by the QGIS repository scan (E741). Decisions and results are unchanged. 1.1.0 Basemaps in QGIS and in the HTML report with current imagery only, because a picture older than the design hides new houses and roads: OpenStreetMap live; detailed Esri World Imagery (0.3-0.5 m in Indonesian towns, your own ArcGIS key) with the capture date at the map centre read from Esri's official metadata service and a warning when it is older than 12 months; the newest cloud-free Copernicus Sentinel-2 quarterly mosaic (10 m, your own free account; published within a month after each quarter, cloudy spots filled from earlier quarters, moves forward by itself). No dates are built in. Optical budget values updated to the maximum values of current ITU-T standards, each with its source (fibre 0.40 dB/km G.652 08/2024; splitters 1:4 7.4 dB and 1:8 10.5 dB G.9940 12/2023; connector 0.5 dB G.671 11/2025; splice 0.15 dB; class B+ 13-28 dB G.984.2); the 17 test decisions are unchanged. English interface with plain-language decision names, tooltips and an offline Help and Quick Guide with glossary. No company or brand names in the plugin: neutral labels, optional company labels in a local istilah.json. KMZ icons embedded in the file. HTML report redesigned with the Plus Jakarta Sans typeface (Tokotype, Jakarta; SIL OFL), a glossary and OpenStreetMap road lines stored for offline use. OpenStreetMap and Overpass use follows the server policies (application User-Agent, 30-60 s pause when the server is busy, own server configurable). New logo. Clearer error messages. 1.0.3 Road download retries when the public server is busy; a failed area no longer stops the others. 1.0.2 Accuracy test against the designs already in the compilation; feeder numbering per POP fixed. 1.0.1 Input checks follow ISO 19157-1:2023; fuzzy matching only for names, never numbers; digit-swapped cable sizes flagged. 1.0.0 First release.
